# LYRA pod firmware

ESP32-S3-DevKitC-1-N8R8 + MyoWare 2.0 (ENV, with RAW for data collection) + BMI270. EXPERIMENTAL research
prototype, not a medical device. A possible event is never a diagnosis. The phone shows
"Possible convulsive seizure detected. This is not a diagnosis."

## Status

## Layout

```
components/lyra_pod/
  lyra_pod.c/.h      streaming runtime: per-stream ring buffers, 4 s / 2 s windows from t = 0,
                     per-window clock check, lyra_step(), BLE event payloads, cancel, device status
  lyra_ble.c/.h      BLE payload codec, byte-exact with mlm/src/lyra_mlm/ble.py (draft protocol v1)
  lyra_logline.c/.h  data-collection line format (pod -> USB serial -> mlm/scripts/pod_logger.py)
../mlm/c99/          detector sources (single source of truth; the firmware build references them)
../mlm/export/c99/   generated forests (regenerate after any model change)
```

## What the ESP-IDF layer must do

1. **Clock:** use `esp_timer` microseconds, as seconds since session start (double), for every stream.
2. **ENV:** the MyoWare ENV pin on the ADC at **50 Hz**, converted to **mV** with ESP-IDF ADC
   calibration. Call `lyra_pod_push_env(t, mV, flag)`. On a read error, flag it `LYRA_FLAG_INVALID`;
   never repeat or interpolate a sample.
3. **IMU:** BMI270 at **25 Hz** ODR with the ranges the model was trained at (**±8 g, ±1000 deg/s**).
   Timestamp each sample at the data-ready interrupt, convert LSB to g / deg/s, then call
   `lyra_pod_push_imu`.
4. **Loop:** one task calls `lyra_pod_tick(now)` every 100–250 ms. Never call it from an ISR.
   - In the callback, notify the phone with `event_payload` whenever `has_event_payload` is set (an
     event starts or ends).
   - `step.status` SUPPRESSED is never a negative and is never shown as "no seizure".
5. **Operating point:** call `lyra_pod_init(&pod, &cfg, lyra_multimodal_rf_predict, lyra_simenv_rf_predict,
   LYRA_ORIGIN_HARDWARE)`. Set `cfg` = {entry **0.97**, exit 0.45, 3 windows, 6.0 s gap, 60 s
   cooldown}: the frozen "multimodal + fallback" point in `mlm/models/frozen_pipeline.json`. Use
   `LYRA_ORIGIN_SIMULATED` for any bench run on generated signals.
6. **Cancel:** the pod button (GPIO interrupt, handed off to the task) calls
   `lyra_pod_cancel(now, LYRA_CANCEL_ON_POD, payload)`. A write to the phone-command characteristic
   calls `lyra_pod_on_phone_command()`:
   - 0: indicate the confirmation payload;
   - 1: stale event, ignore;
   - −1: reject the write.
   Event status goes out as an **indication**.
7. **Device status:** periodically call `lyra_pod_device_status()` with the MAX17048 battery reading
   and notify.
8. **Phone config:** decode writes with `lyra_ble_unpack_device_config()`.
   - In v1, only `countdown_s` is applied; rates and window length are fixed by the trained model.
   - GATT UUIDs and properties: the DRAFT table in `mlm/docs/BLE_PROTOCOL.md`, also defined as
     `LYRA_GATT_*_UUID` in `lyra_ble.h`, pending owner approval.
9. **Data-collection mode** (build option, never in the deployed build):
   - Also sample MyoWare RAW at **1000 Hz**.
   - Write `lyra_logline` lines over USB serial (header first, then E/R/I samples and M markers).
   - The capture is converted with `mlm/scripts/pod_logger.py`
     (`mlm/docs/POD_DATA_PROTOCOL.md`). No consent, no session.

### Bring-up checks before trusting any output

- **Clock check:** the per-window check needs each stream's median interval within 5000 ppm of 50 Hz
  / 25 Hz. If the BMI270's real ODR differs by more than 0.5%, every multimodal window becomes
  UNSYNCHRONIZED and is suppressed. Measure the ODR on the board first. Then decide whether to
  correct the declared rate (the features assume the nominal rate) or to change the threshold.
- **Domain gap:** the forests were trained on SeizeIT2 simulated ENV (µV-derived) and a chest IMU.
  On the pod they get MyoWare ENV in mV from the upper arm. Until the pod data protocol has been run
  (`scripts/pod_report.py`), pod scores have **no validated meaning**.
- **Parity on the board:** run `lyra_step` on stored test windows on the S3, compare with the host,
  and time it (`esp_timer`).

## Build notes

- **ESP-IDF:** not installed. Install it before writing the platform layer, preferably into
  `~/esp/esp-idf`; it brings its own toolchain.
- **Compiler for size checks:** Espressif crosstool-NG `esp-14.4.0_20261030` in
  `~/.espressif/tools/xtensa-esp-elf/`, used by `mlm/scripts/size_esp32s3.py`.
- **Flags:** `-mlongcalls` (the ESP-IDF default), `-std=c99`. The forests must stay one function per
  tree: one ~370 KB function exceeds Xtensa's jump and literal reach.
- **Partition:** use an app partition of at least 1.5 MB. The board has 8 MB of flash, and the
  default 1 MB app partition is too small once NimBLE is added.

## Size on the ESP32-S3 (objects + test link; FreeRTOS, drivers and NimBLE not included)

| | Flash | Static RAM |
|---|---|---|
| Two forests | ~701 KB as objects | 0 |
| Detector + pod core (features, quality, confirmation, `lyra_step`, runtime, BLE codec, log lines) | ~16.4 KB | 54.1 KB |
| **Linked from the pod entry points, incl. libm, soft-float and printf** | **646 KB** | **54.7 KB** |

The largest stack frame is 448 B (`lyra_pod_tick`). Doubles are software-emulated on the S3. The
estimated detector cost is about 30 ms per 2 s window; it still has to be measured.
