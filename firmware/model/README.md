# LYRA detector package for the ESP32-S3 (C99)

> Experimental research component. It is not clinically validated and not a diagnostic device. An opened
> event is a *possible* convulsive event. It is never a confirmed seizure. The app's cancel countdown
> and caregiver workflow apply unchanged.

The package is dependency-free C99 and needs only libm. It is generated and validated by `ml/lyra/`. The
evaluation, selection and resource measurements are in `reports/lyra/lyra_report.md`.

Current export (`lyra-esp32s3-convulsive` 1.0.0): XGBoost 40 trees × depth 4 on all 13 features. Windows are
4 s with a 2 s hop. Threshold 0.015, N=3 to open, M=3 to close, 60 s refractory. Measured with the ESP32-S3
toolchain: 15,898 B flash and 6,024 B SRAM, including one input window.

| File | Origin | Content |
|---|---|---|
| `lyra_feature_spec.h` | generated from `ml/lyra/feature_spec.json` | feature order, rates, window limits, epsilon |
| `lyra_features.h/.c` | hand-written, mirrors `ml/lyra/features.py` | window quality check + 13 features |
| `lyra_model.h` | generated by `ml/lyra/export_c.py` | classifier + Platt calibration → probability |
| `lyra_detector_config.h` | generated | window/hop, threshold, N/M persistence, refractory, max gap |
| `lyra_detector.h/.c` | hand-written, mirrors `ml/lyra/events.py` | candidate-event state machine |
| `lyra_model_test.c` + `test/golden_vectors.bin` | test | Python/C parity on synthetic golden vectors |

## Signal contract (locked decision D12: MyoWare ENV pin)

- **EMG.** Sample the MyoWare 2.0 **ENV** output and do not filter it digitally.
  - The ADC must oversample (≥ 1 kHz). Average each 20 ms bin to get 50 Hz; this is the anti-alias step
    the training data assumed.
  - Convert to the training scale (uV-equivalent of a rectified, 3.6 Hz-smoothed sEMG envelope) with a
    per-device gain calibration. This calibration is **not done yet**. The amplitude features depend on
    it, so the model is not valid on raw ADC counts.
- **IMU.** Use the BMI270 at 25 Hz: accelerometer in m/s² and gyroscope in rad/s, interleaved x,y,z.
- **Windows.** Each window holds `LYRA_WINDOW_ENV_SAMPLES` ENV and `LYRA_WINDOW_IMU_SAMPLES` IMU samples
  ending at the same instant. One window is emitted every `LYRA_HOP_MS`. The window-end time is the event
  timestamp.

## Per window

```c
float x[LYRA_N_FEATURES];
unsigned ev = LYRA_EV_INVALID;
if (lyra_window_valid(env, n_env, acc, gyr, n_imu, ENV_ADC_FULL_SCALE) == LYRA_OK &&
    lyra_features_compute(env, n_env, acc, gyr, n_imu, x) == LYRA_OK)
    ev = lyra_update_event_state(lyra_model_predict(x), window_end_ms);
else
    ev = lyra_update_event_state(NAN, window_end_ms);  /* invalid: the detector holds */
if (ev & LYRA_EV_ALERT) { /* send a possible-event notification over BLE */ }
```

- **Session boundary.** Call `lyra_init_event_state()` (or `lyra_detector_reset()`) at every session
  start, sensor reconnect and recording boundary.
- **Timestamps.** `window_end_ms` must be monotonic milliseconds. uint32 wrap-around is handled.
- **Fixed-hop wrapper.** `lyra_update_event_state_fixed_hop()` exists for callers without timestamps. It
  assumes one window every `LYRA_HOP_MS` with no gaps.
- **Reentrancy.** `lyra_features_compute` uses static scratch buffers (2,008 B of doubles for
  the exported configuration) and is not reentrant.

## Build and test on the host

```bash
cc -std=c99 -O2 -Wall -Wextra -Werror -pedantic -I firmware/model firmware/model/lyra_model_test.c \
   firmware/model/lyra_features.c firmware/model/lyra_detector.c -lm -o /tmp/lyra_model_test
/tmp/lyra_model_test firmware/model/test/golden_vectors.bin
```

`firmware/esp32s3_app/` is a minimal ESP-IDF v5.5 project that only links the package, so the linker can
measure its size. It is not product firmware.
